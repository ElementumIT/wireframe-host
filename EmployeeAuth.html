Unit Claiming App — Employee Authorization Wireframe

Second screen (DataCollectionSteps=1: GetEmployeeAuthorization). Source: UnitClaimingMainForm.cs, UnitClaimingMainFormController.cs. 880×520 client area.

Color Key

  • Next/Enter — primary action (green)
  • Previous — disabled at this step (gray)
  • Step logic annotations (blue)
  • Navigation notes (green)
  • Variation notes (amber)

Step: GetEmployeeAuthorization

  • Control: EmployeeNumber (implements IDataCollectionControl)
  • Input: any 5-digit integer (policy since 2/24/2015)
  • On Enter/Next: save badge, cache in MDI parent, LoadSecurityModel()
  • Security: missing record → default access (User=true, Overrider=false, Admin=false, KeyboardEntry=false)
  • DeniedAccess: step 0 shown if UnitClaimingUser=false
  • Plant: loaded from user config, set on skid record
  • Advances to: GetPartNumber (step 2)

Idle / Session

  • IdleTimer (configurable) resets on any input
  • Warning countdown in MDI status bar
  • Timeout → AfterSave() → return to Main Menu
  • Employee badge timeout separate (EmployeeBadgeTimeoutSecs)

Navigation

  • Previous — DISABLED at this step
  • Next (Enter) — enabled, green, Enter key = Next
  • Badge cached in MDI parent for session
  • Badge timeout enforced separately

Variations

  • Same screen for ALL variations (Standard, Reprint, LowVolume, Combo, BoxLabel, MachineNumber, Location, KitClaiming)
  • Only FormHeaderText changes
