Unit Claiming App — Serial Number Entry Wireframe

Third screen (DataCollectionSteps=3: GetSerialNumber). Source: SerialNumber.cs, UnitClaimingMainForm.cs. 880×520 client area.

Color Key

  • Next/Enter — primary action (green)
  • Previous — enabled (gray)
  • Validation error (red)
  • Variation logic (amber)
  • Step logic (blue)

Step: GetSerialNumber

  • Control: SerialNumber UserControl (427×262), implements IDataCollectionControl
  • Input: tbSerialNumber (271×20) — scan or type
  • Output: GetInput() → ParseSerialFrom2DIf2DFound(); FASCell property populated from serial
  • Validation: lblInvalidSerial (red, hidden unless error)
  • Debug: Sample serial list (config EnableDebuggingHelpers)

Variation-Specific Validation

  • BoxLabel: any serial allowed (even blank)
  • StandardReprint: must exist in DB; strips leading 'S'/'s'
  • LowVolume: duplicate check + FAS Cell required + Julian date warning (>1 day)
  • Standard/Combo: duplicate serial check within combo; FAS Cell required

FAS Cell

  • Populated via GetFASCellFromSerial() — extracts Production Line Code from serial
  • Saved to skid.FASCell on Next
  • Required for LowVolume & Standard/Combo

Navigation

  • Previous → back to Part Number (enabled)
  • Next (Enter) → advances to GetPalletQuantity (4)
  • Enter = Next, Esc = Previous
  • BoxLabel special: on Next → skips to GetSkidIdFromLicensePlate (12)

Debug Helpers

  • Sample serial list (config EnableDebuggingHelpers)
  • Double-click sample → fills tbSerialNumber
  • label3 + listBox1 visible only when debugging enabled
