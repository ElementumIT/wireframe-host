Unit Claiming App — Skid Complete Wireframe

Sixth screen (DataCollectionSteps=6: SkidDataComplete). Terminal step — review, save/print, loop back to Main Menu. Source: PalletInfoDisplay.cs, UnitClaimingMainForm.cs. 880×520 client area.

Color Key

  • Primary action (Print/Save) — green
  • Previous — enabled (gray)
  • Variation logic (amber)
  • Terminal step warning (red)
  • Step/Print logic (blue)

Step: SkidDataComplete (6)

  • Terminal step — no Next button
  • Previous → back to Skid Weight (enabled)
  • Action button text varies by variation:
  • Standard/Combo: "Print Labels"
  • StandardReprint/BoxLabel/MachineNumber/Location/StdExtModelNum: "Print Label"
  • LowVolume/KitClaiming: "Save"
  • Enabled only when no blocking exceptions

On Save/Print

  • Validate: no blocking exceptions
  • Switch on variation → PrintLabels / PrintBoxLabels / PrintMachineNumber / PrintLocation / Save only
  • Combo: prints both skids sequentially
  • Extended Model Num: prints skid2 only
  • History/Reprint: no DB write, prints from saved record
  • On success → methodToCallToRefresh() → AfterSave() → Form1_Load() → ShowMainMenu()

History / Reprint Mode

  • InHistoryMode=true → no DB writes for Standard/Combo
  • StandardReprint: SaveReprintInfoToDb + PrintLabels with reprintRec
  • Extended Model Num: prints skid2 only
  • Combo history: both skids with separate reprintRec
  • lblPassFail VISIBLE in history/reprint
  • btnClear HIDDEN in history mode

Navigation & Interactions

  • Previous → back to Skid Weight (enabled)
  • NO Next button (terminal step)
  • Double-click Employee/Model/Pallet/Weight in right panel → jump to that step
  • Idle timeout → auto-triggers AfterSave()
  • AfterSave() = Form1_Load() → ShowMainMenu() → resets for next skid

Right Panel: Full PalletInfoDisplay

  • 4-col × 7-row tableLayoutPanel
  • Combo shows dual: "Val1 / Val2"
  • Labels bold during data entry
  • Shows Pass/Fail in history/reprint
  • Double-click values → jump to step
